# Go CLI & Tooling Guidelines

## 1. Testable entrypoint

`main` only wires OS resources into a pure function:

```go
func main() {
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
    defer stop()
    os.Exit(run(ctx, os.Args[1:], os.Stdin, os.Stdout, os.Stderr))
}

func run(ctx context.Context, args []string, stdin io.Reader, stdout, stderr io.Writer) int {
    // parse flags from args, write output to stdout, diagnostics to stderr
}
```

Tests call `run` with `bytes.Buffer`s — no subprocesses, no global state (see `go-test`).

## 2. Flags & commands

- Stdlib `flag` with `flag.NewFlagSet(name, flag.ContinueOnError)` for simple tools. NEVER use the global `flag.CommandLine` in testable code.
- `github.com/spf13/cobra` (or `github.com/alecthomas/kong`) when you need nested subcommands, completions and rich help. Use `RunE` (return errors), `cmd.Context()`, `cmd.OutOrStdout()`/`cmd.ErrOrStderr()`; set `SilenceUsage: true` so runtime errors don't print usage.
- Config precedence: flags > env vars > config file > defaults. Document it in `--help`.
- Validate all flags upfront and report every problem at once.

## 3. Output discipline

- **stdout** = program output (data meant to be piped). **stderr** = logs, progress, prompts, errors.
- Support machine-readable output (`--output json`) for anything scripts may consume; keep human output stable-ish too.
- Don't print colors/spinners when stdout is not a TTY (check with `golang.org/x/term`), and respect `NO_COLOR`.
- Use `slog` with a text handler on stderr for diagnostics, `-v`/`--verbose` raises the level (see `go-observability`).

## 4. Exit codes & errors

- `0` success, `1` generic failure, `2` usage/flag error. Document any others.
- Print a single clear error line to stderr (`toolname: open config.yaml: no such file or directory`), not a stack trace.
- Only `main` calls `os.Exit`.

## 5. Behavior

- Respect cancellation (Ctrl-C): long operations take `ctx`, clean up temporary files, and exit with code 130 when interrupted, if meaningful.
- Read from stdin when the input argument is `-` or absent and stdin is piped.
- Destructive operations require confirmation or `--yes`/`--force`; support `--dry-run`.
- Write files atomically (write to temp in the same dir, `Sync`, `Rename`).
- Use `os.UserConfigDir()` / `os.UserCacheDir()` for per-user files.

## 6. Build & release

- Inject version info with `-ldflags "-X main.version=..."` or read `runtime/debug.ReadBuildInfo()` (VCS info embedded automatically).
- `CGO_ENABLED=0` static builds; cross-compile with `GOOS`/`GOARCH`. Use GoReleaser for multi-platform releases, checksums and SBOMs.
- Embed static assets/templates with `//go:embed`.
- Code generators: run via `//go:generate`, output files start with `// Code generated by <tool>; DO NOT EDIT.` and are gofmt'd (`go/format`).
